`countryRouting`: `default` = el primero; **`MX` esta vacio**; el resto vacio.

**Como elige el caller ID el dispatch del agente**
(`_retellPickNumberForDestination`, index.js ~14520 — orden de prioridad):
1. si `retell_config.fromNumberId` esta seteado y ese numero esta en el pool
   y activo -> **ese, sin rotar**
2. si hay `countryRouting[pais destino]` -> ese
3. si el pool tiene mas de 1 numero -> **rotacion round-robin sobre TODOS los
   numeros activos**
4. `countryRouting.default` -> ese
5. el primero del pool

**La consecuencia que hay que evitar**: hoy, con `fromNumberId` vacio y `MX`
vacio, el agente rotaria sobre los 3 numeros. Si solo algunos estan importados
en Retell, `create-phone-call` falla para los otros con un error de
`from_number` desconocido — y el lote sale a medias sin que se rompa nada
visible (el dispatch reporta el error por lead y sigue).

**El pool es COMPARTIDO**: `telnyx_config.numbers` es la misma lista que usa
la rotacion del dialer WebRTC humano (`pickNumberForDestination`,
public/app.js ~2270). Un numero marcado `active:false` desaparece para los dos
— no sirve como forma de "reservarlo" para el agente.

**Import de numeros a Retell** (26-RESEARCH §1.B.9, VERIFIED):
`POST https://api.retellai.com/import-phone-number`, `Authorization: Bearer
<RETELL_API_KEY>`, body:
`{ "phone_number": "+1786...", "termination_uri": "<FQDN de terminacion de
Telnyx segun la region SIP elegida>", "sip_trunk_auth_username": "...",
"sip_trunk_auth_password": "...", "transport": "TCP", "nickname": "Agente IA
- linea 1" }`

**Config del SCM**: `PUT /api/retell/config` (admin) acepta
